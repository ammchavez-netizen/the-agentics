## 2. How CrewAI works

CrewAI organizes an AI workflow using agents, tasks , and a crew. An agent represents a role with a specific goal, background, and language model. A task defines the work that an agent must perform , including its description and expected output. A crew brings the agents and tasks together and controls how they execute.

My project uses Process.sequential , meaning the tasks execute in a defined order. The Research Analyst starts by identifying possible causes and diagnostic steps for the RHEL 9 certificate issue . The Technical Writer uses the research to prepare an explanation . The Editor improves the report and flags unsupported claims , while the Checker reviews the final result for errors and missing information.

The expected_output field helps guide each agent toward a particular result . For example, requesting three key facts and two open questions makes the research task more specific than simply asking the agent to analyze a problem .

I also learned that task descriptions and agent goals need to be consistent . If an agent is instructed to omit diagnostic commands while its task requires those commands, the output may not meet expectations . Simplifying task instructions can reduce prompt size, although the previous tasks' outputs may still contribute to the context sent to the model .

## 4. Choosing a framework

I would choose CrewAI for a project like this because its agent-and--task structure is straightforward to understand. The Linux troubleshooting workflow can be divided into separate responsibilities, allowing one agent to analyze the problem , another to write the report, and others to review it. The sequential process also makes the intended order of work easy to define.

Another framework from class is LangGraph. LangGraph would be useful if I needed more control over the workflow, including conditional transitions, shared state , retry logic, or returning to an earlier step when a report fails validation. For example, a troubleshooting system could check whether the report includes certificate SAN verification and Apache configuration checks, then send the report back for revision if required information is missing .

However, implementing that control flow would require more explicit workflow and state management than my basic CrewAI example . CrewAI is convenient when the process can be described as a team of agents completing tasks in sequence. LangGraph may be a better fit when the workflow needs complex branching or repeated validation .

For this project, CrewAI provides a simple way to experiment with role-based collaboration. The request-size error also showed me that a multi-agent workflow can accumulate context as tasks progress , so keeping prompts and intermediate outputs concise is important regardless of the framework.
